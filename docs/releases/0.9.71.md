# fx 0.9.71 — IR for atomics · MMIO · CapDict

**Language package** for [ledocorp/fxlang](https://github.com/ledocorp/fxlang)  
**Tag:** `v0.9.71` (when published)  
**On** [0.9.70](0.9.70.md).

---

## Highlights

| Area | What landed |
|------|-------------|
| **Atomic IR** | `Atomic<i32>` ops (`new` / `load` / `store` / `fetch_add` + explicit orders) lower on the **IR → native** path when QBE is staged. Still emit-C → C11 `<stdatomic.h>`. |
| **MMIO IR** | `MmioCap` + `mmio_read32` / `mmio_write32` on IR → native (hosted mint proof). emit-C stays readable `volatile` via cap. |
| **CapDict IR** | Cap dictionary mint + invoke on IR → native (visible C vtable layout). Facets remain as in **0.9.69+**. |
| **Examples** | `examples/kern_atomic/`, `examples/kern_mmio/`, `examples/capdict_writer/` — dual-path exit **42** (`--emit-c` and `--backend ir` when QBE is present). |
| **Carry-forward** | `--freestanding`, facets, loans, iterate/FXCACHE, native-first Auto from prior cuts. |

**IR honesty:** Auto / built-in engine IR claims Atomic · MMIO · CapDict · Facet when QBE is staged. **IRQ** IR remains out of claim — prefer `--emit-c`. Strict live `--driver sh --backend ir` still covers the sealed micro-corpus only; for Atomic/MMIO/CapDict use Auto/`--emit-c` or IR on the default engine path.

**Ship configs:** Auto · emit-C · IR when QBE staged (incl. Atomic/MMIO/CapDict) · GPL-3.0 · Win+Linux x86_64.
